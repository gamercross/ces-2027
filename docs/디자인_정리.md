## 2. 공식 CES 앱 쪽 원칙

공식 앱 기준표 [docs/공식앱_기준표.md](공식앱_기준표.md)는 #47로 main에 들어왔다. 기능을 비교한 표라 화면 짜임(탭 · 색)은 담지 않고, "공식 앱의 이름 · 로고 · 화면 모양을 베끼지 않는다"를 약속으로 적었다. 공개 자료로 확인한 것은 다음뿐이다.

- 공식 앱은 일정 만들기 · 전시사 즐겨찾기 · 3D 지도에서 부스 누르기(회사 정보 · 사진 · 링크 · 길 안내) · 교통 · 번역 · QR 연락처 · AI 챗봇을 한 앱에 담는다. 출처: https://www.ces.tech/app · https://apps.apple.com/app/id6443741077 · https://www.eventbase.com/news/unlock-ces-2026-why-you-need-the-official-mobile-app (확인 2026-11-21)
- 탭 이름 · 탭 개수 · 색 · 글꼴 같은 화면 구성은 공개 글에서 확인하지 못했다. (11/22 갱신: 스토어 홍보 화면 4장을 보니 메뉴(햄버거) + 검색 머리이고 본 화면에는 아래 탭이 없었다. 자세한 것은 [참고/ces2026-앱-살펴보기.md](참고/ces2026-앱-살펴보기.md).) 2027 판이 2026과 같다는 보장도 없다.

그래서 공식 앱의 모양은 따르지 않는다. 이 앱은 비공식이고 공식 이름 · 로고 · 화면 모양을 베끼지 않는다는 것이 기준표의 약속이다. 공식 앱에서 가져온 것은 "일정 · 지도 · 전시사 찾기가 화면을 바꿔 한 걸음에 닿는다"는 짜임뿐이고, 우리 앱은 이미 아래 탭으로 그렇게 되어 있다.

## 3. 고른 기준

한 줄: 눈이 편한 파스텔 바탕 + 남색 글씨, 한 줄(최대 560px) 폰 화면, 톤 차이로만 나누는 평평한 면, 시스템 한글 고딕 하나.

- 값은 `web/tokens.css` 한 곳. 화면은 이름만 쓴다. 지도를 그리는 코드는 `web/tokens.js`로 같은 값을 읽는다(브라우저에서는 `tokens.css`에서 읽고, Node 시험에서는 기본값을 쓴다).
- `scripts/smoke.mjs`가 세 가지를 맞춰 본다: 기본값이 `tokens.css`와 같은가, 화면 파일에 색 값을 직접 적지 않았는가, `app.css`에 그림자 · 그라데이션이 없는가.
- 바꾼 것: 단추 두 모양을 한 가족으로(둥근 네모 12px, 고른 것은 민트 + 2px 강조 테두리), 알약 · 그림자 · 1px 선 없앰, 묶음 제목 18px 진한 글씨, 줄 안의 단추는 묶음색으로 떠올라 구별, 탭에 선 그림 + 이름(한 손 엄지 기준 64px), 넓은 화면에서도 탭이 가운데 한 줄에 섬, QR 바탕 순백 → 카드색.
- 바꾸지 않은 것: 기능 · 데이터 · 로직, 화면의 글과 차례, 클래스 이름(다른 일꾼의 브랜치가 그대로 합쳐지도록).

## 4. 메인 틀 · UX (11/21 더한 방향)

이재엽: "디자인 작업들은 메인 틀을 준비해 주고, 사용자들이 편하게 사용하기 위한 UX들이 메인이 되어야 해." 그래서 꾸밈(3절)보다 틀과 쓰는 길을 먼저 고쳤다. 기준은 design.md의 "메인 틀" · "UX".

- 아래 탭 여섯 → 다섯(홈 · 회사 · 동선 · 지도 · 일기). 주제 판은 회사 화면 위의 "주제 판" 단추와 첫 화면 바로 가기로 간다. 세션 · 셔틀 · 만난 사람은 탭에 넣지 않고 바로 가기에 둔다("더 보기" 같은 숨기는 층을 만들지 않는다).
- 하위 화면에 "뒤로", 느린 망에 "불러오는 중", 못 불러오면 "다시 열기", 틀린 주소는 "없는 화면", 인터넷이 끊기면 머리 아래 한 줄. 모두 `web/frame.js` 한 곳.
- 첫 화면 맨 위에 "지금 갈 곳"과 "바로 가기". 첫 화면의 같은 단추 겹침(내 명함 보기 · 회사 찾기 · 물어보기가 머리 · 탭 · 바로 가기와 겹침)을 없앴다. 명함이 없을 때만 "명함 만들기 · 회사 찾기"가 남는다.

쓰는 길, 첫 화면에서 몇 번 눌러 끝나나 (폰 360×740, 관심 회사 셋을 넣은 상태):

| 쓰는 길 | 전 (main aa7e21e) | 후 |
|---|---|---|
| 다음 세션 찾기 | 동선 탭 → "세션 일정" 2번 | 바로 가기 "세션 일정" 1번 (스크롤 없음) |
| 부스 찾아가기 | 동선 탭 → "구글맵 길찾기" 2번 (단추는 동선 화면 602px, 무엇이 다음인지는 동선을 열어야 보임) | 첫 화면 "구글맵 길찾기" 1번 (369px, 다음 갈 곳이 첫 화면에 보임) |
| 만난 사람 남기기 | 내 명함 → "남의 명함 받기" 2번 | 바로 가기 "만난 사람" → "남의 명함 받기" 2번, 만난 사람 목록은 1번 |
| 물어보기(앱 안 자료 찾기) | 첫 화면 "물어보기" 1번 | 바로 가기 "물어보기" 1번 (같음) |
| 셔틀 노선 · 시간표 | 첫 화면을 2,543px까지 내려 "셔틀 노선 · 시간표 보기" (스크롤 + 1번) | 바로 가기 "셔틀" 1번 (스크롤 없음) |

화면 사진은 `docs/screens/40` ~ `54`.

## 5. 남은 것
- 쓰는 폰에서 QR이 새 색(카드색 바탕 + 남색)으로 잘 읽히는지는 실제 폰으로 확인하지 못했다(`docs/테스터_안내.md`의 확인 목록에 넣을 것).
- 화면 그림 `docs/screens/`의 옛 39장은 그대로 두고, 새 판은 40번부터 붙였다.
- 셔틀(#49)이 들어와 바로 가기에 "셔틀"이 저절로 생겼다. 첫 화면 "오가는 법" 안의 셔틀 · 자율주행 단추는 바로 가기와 겹쳐 한 줄 안내로 바꿨다.
- 동선 · 지도 화면의 "다음 갈 곳"은 첫 화면의 "지금 갈 곳"과 같은 자료다. 그 화면 안에서 쓰는 일(봤다 · 차례)이 있어 그대로 두었다. 하나로 줄일지는 실제 시험 뒤에 본다.
- 숫자는 브라우저 흉내(데스크톱 Chromium, 360×740)로 잰 것이다. 실제 폰 · 한 손 시험(이슈 #13)에서 다시 잰다.
