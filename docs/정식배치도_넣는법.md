# 정식 배치도가 열리면 넣는 법

지금 홀 안 부스 자리는 모두 짐작이다. 공식 배치도가 열리면 아래 차례로 바꾼다. 넣을 자리와 그 자리를 읽는 코드는 이미 있다. 아직 없는 것은 "공식 배치도에서 좌표를 뽑는 일"이다. 배치도가 열려야 그 꼴을 알 수 있다.

## 0. 미리 만들어 둔 것 (2026-11-22)

- **열렸는지 자동으로 본다:** `.github/workflows/floorplan-watch.yml`이 매일 한 번 공식 전시사 검색의 `validHalls`를 읽는다(`node scripts/check-floorplan.mjs`). 비어 있지 않으면 GitHub 이슈 하나("정식 배치도가 열렸다")를 만들어 알린다. 이미 열린 이슈가 있으면 또 만들지 않고, 사이트를 못 읽은 날은 "모름"으로 끝낸다.
- **좌표를 넣는 도구:** `node scripts/import-booth-spots.mjs 입력.json`(보기만) · `--write`(`data/booth-spots.json`에 합침) · `--write --official --exhibitors 전시사.json`(그 장소의 부스를 다 채웠을 때만 `places.json`의 boothSpots를 official로). 배치도 그림의 좌표를 장소의 모양 상자에 맞춰 늘이고 옮기며, 상자에서 10% 넘게 벗어난 것은 거르고(20%를 넘으면 쓰지 않는다), 방향이 거꾸로면 `--swap · --flipx · --flipy`로 맞춘다. 입력 꼴은 파일 위쪽 설명에 있다.
- **아직 모르는 것:** 배치도의 실제 꼴(그림 · 좌표가 든 응답 · PDF). 그 꼴을 위 입력(`{ place, booths: { 부스: [x, y] } }`)으로 바꾸는 작은 변환은 열린 뒤에 쓴다.
- **부스 칸 크기(11/26, R66 덧):** 지도는 부스마다 네모(대략)를 그린다. 배치도에 부스 네모 크기가 있으면 입력을 `[x, y, 너비, 높이]`로 주면 같은 배율로 미터로 옮겨 `data/booth-spots.json`에 `[x, z, 너비, 깊이]`로 들어가고, 그 칸은 실제 자리 · 크기로 그려진다. 크기가 없으면 `[x, y]`(가운데만)이고 칸 크기는 그 홀의 대략 크기를 쓴다.

## 1. 열렸는지 보기

- 2026-11-19 밤에는 닫혀 있었다. 공식 전시사 검색(exhibitors.ces.tech)의 `Vue.MYS.validHalls`가 빈 칸이었고 배치도 주소가 홈으로 돌아갔다 (`data/출처.md`).
- 열리면 전시사 검색 화면에 "Floor Plan"이 생기고 홀을 고를 수 있다.
- 열렸으면 이재엽에게 알리고 아래를 한다.

## 2. 넣는 차례

1. 홀 하나를 고른다 (작은 홀부터: LVCC 사우스 홀 3).
2. 공식 배치도에서 그 홀의 부스마다 자리를 얻는다. 꼴은 열려 봐야 안다 (그림 · 좌표가 든 응답 · PDF 가운데 하나일 것이다).
3. 배치도의 좌표를 이 레포의 좌표(실제 미터, `data/places.json`의 `geoRef`. 11/26 R66부터)로 옮긴다. 넣는 도구는 배치도의 네모(`plan.bbox`)를 그 장소 `poly`의 네모에 맞도록 늘이고 옮긴다. 층이 겹쳐 한 윤곽을 나눈 홀(노스 · 센트럴, 사우스 1 · 2 · 3, 베네시안 A-D · G)은 나눈 칸이 실제 홀 칸과 다를 수 있으니, 그 홀의 배치도 모서리 둘을 실제 자리(위도 · 경도)와 견주어 보고 넣는다.
4. `data/booth-spots.json`의 `places` 아래에 적는다:

   ```json
   {
     "edition": "배치도를 받은 날짜",
     "source": "배치도 주소",
     "places": {
       "LVCC_S3": { "40112": [812, 1250], "40118": [820, 1250] }
     }
   }
   ```

5. 그 홀의 부스를 다 적었으면 `data/places.json`에서 그 장소의 `boothSpots`를 `"official"`로 바꾼다. 화면의 "자리는 짐작이다"가 그 장소에서는 "공식 배치도다"로 바뀐다.
6. `cargo run -p ces-data -- check-places`와 `node scripts/smoke.mjs <지은 폴더>`를 돌린다. 살피기는 적힌 부스가 그 자리로 가는지, 공식이라고 적은 장소에 정식 자리가 들어 있는지 본다.
7. 걷는 차례(`web/route.js`의 `walkKey`)는 부스 번호로 통로를 짐작한다. 정식 자리가 들어오면 자리의 좌표로 세우도록 고친다 (이때 같이 한다).

## 3. 일부만 열렸을 때

홀마다 따로 바꿀 수 있다. 적힌 부스만 정식 자리를 쓰고 나머지는 짐작 그대로다. 한 홀을 반만 적었으면 `boothSpots`를 `"guess"`로 둔다.

## 4. 아직 정하지 않은 것

- 배치도에서 좌표를 손으로 옮길지, 자료 도구(Rust)가 받아 오게 할지. 꼴을 본 뒤 정한다.
