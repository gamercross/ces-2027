# 단계별 디자인 준비

이 문서는 코드가 아니라 **밑그림**이다. 5 ~ 8단계를 짓는 일꾼이 단계를 시작할 때 해당 장을 읽는다. 공식 앱에서 본 것은 [ces2026-앱-살펴보기.md](ces2026-앱-살펴보기.md)에 있고, 여기에는 거기서 배운 점만 쓴다.

- 공식 앱 파일은 받지 못했다(이 Mac이 App Store 앱을 못 받고, 안드로이드 설치 파일 미러는 봇 차단). 그래서 **스토어에 공개된 화면 그림 4장 · 공식 소개 글 · 앱을 만든 회사의 안내 글**에서 본 것만 근거다. 공식 앱의 지도 화면 · 설정 화면 · 사이드 메뉴 안은 보지 못했다.
- 공식 앱의 코드 · 그림 · 문구 · 색 값을 가져오지 않았다. 모양은 말로만 적었고, 크기 수치는 스토어 그림에서 눈금으로 잰 어림(±3)이다.
- 디자인은 `design.md`를 따른다: 무채색(회색 단계) + 강조색 하나, 글 적게, 폰 360px, 쓰기 편한 UX가 꾸밈보다 먼저. 아래 "줄 · 단추 · 시트" 규칙은 그 위에 더하는 것이고, 부딪치면 `design.md`가 이긴다.

## 0. 모든 단계에 같은 규칙

### 0.1 줄 하나의 꼴

목록의 줄(동선의 회사 · 일기 · 만난 사람 · 세션)은 모두 같은 꼴로 짠다.

```
┌──────────────────────────────────┐ 높이 64 이상
│ (1)  이름 한 줄 ........ 말줄임    [길찾기] │
│      보조 한 줄: 홀 · 부스 · 때        │
└──────────────────────────────────┘
```

- 왼쪽 표시 하나(번호 · 시간 · 아이콘) / 가운데 제목 한 줄(16px, 굵게) + 보조 한 줄(14px, 보조 글자) / 오른쪽 **주 단추 하나**.
- 줄 한 칸에 단추는 **최대 둘**(주 단추 + 아이콘 단추 하나). 나머지 동작은 줄을 누르면 열리는 카드(0.3)에 둔다.
- 줄 전체가 눌린다(누르는 곳 44px 이상). 줄 사이는 얇은 선이 아니라 8px 여백과 바탕 톤 차이.

### 0.2 단추는 둘뿐

`design.md` 그대로: **검정 칠한 단추** 하나(화면에 하나) + **글자 단추**(밑줄). 회색 면 단추(지금 일기 맨 위 "듣기 · 대화 칸 · 만난 사람" 같은 것)는 칩과 구별이 안 되므로 새로 만들지 않는다. 칩은 "고르는 것"에만 쓴다(날짜 · 홀 · 글자 크기).

### 0.3 카드(시트) 하나

회사 · 만난 사람 · 일기 · 세션의 자세한 모습과 덜 쓰는 동작은 **같은 아래에서 올라오는 카드**로 연다. 4단계에서 지도의 회사 카드가 이미 이 모양이다(이름 24px · 부스 · 홀 · 분야 · 자리 짐작 · 담기 · 길 안내). 카드를 새로 만들지 말고 `web/mapsheet.js`의 틀을 같이 쓴다. 카드는 열리면 아래 탭 위 가림(도크)을 걷는다.

### 0.4 글자 수

- 화면 맨 위 처음 보이는 한 화면(360 × 740, 스크롤 전)에 **설명 글은 두 문장 이하**, 제목 · 단추 · 줄은 따로 센다.
- 제목은 한 줄. 같은 탭 이름이 아래에 켜져 있으므로 큰 제목(34px)은 줄이거나 뺀다(8단계 목록 3번).
- 같은 말(예: "자리는 짐작")을 줄마다 되풀이하지 않고 묶음 위에 한 번.

### 0.5 360px 점검표 (단계마다 사진과 함께)

1. 가로 넘침 0 (글자 크기 네 단계 모두 — 7단계 뒤부터).
2. 누르는 곳 44px 이상, 주 단추 52px.
3. 아래 탭 위로 내용이 가려지지 않는다(마지막 줄이 도크에 잘리지 않는다).
4. 처음 보이는 한 화면에 주 단추가 하나.
5. 비었을 때 · 못 불러왔을 때 · 인터넷 없을 때 화면(`frame.js`)이 있다.

## 1. 5단계 동선

**한 줄:** 관심 회사를 날짜별 걷는 차례로 세우고, 지도와 같은 번호로 잇고, 회사 카드를 크게 연다.

지금 동선 화면(`web/views/plan.js`)의 문제: 줄 하나에 단추가 일곱 ~ 여덟 개(봤다 · 명함 이벤트 · 날짜 고름 · 위로 · 아래로 · 빼기 · 길찾기 · 일기)이고, 폰 첫 화면의 위쪽 절반을 "지금 갈 곳 + 제목 + 긴 안내 + 종이 명함 묻기 카드"가 차지해 정작 날짜별 차례가 아래로 밀린다. 아래에는 도크(날짜 채우기 · 걷는 차례로)와 탭이 두 겹으로 겹쳐 마지막 줄이 가려진다(`docs/screens/무채색-테마/후-light-plan.png`).

### 화면 틀 ①: 동선 (360px)

```
┌──────────────────────────────────┐
│ [아이콘] 글로벌 어학연수 [비공식]   │ 머리 (스크롤하면 올라간다)
├──────────────────────────────────┤
│ 동선                      [차례 정리]│ 제목 24px + 글자 단추 하나
│ ┌────┬────┬────┬────┬────┐        │
│ │ 1/6│ 1/7│ 1/8│ 1/9│미정│        │ 날짜 칩 한 줄(고정, 칸 64 × 56)
│ │ 6곳│ 4곳│ 5곳│ 0곳│ 2곳│        │ 칸 아래에 곳 수
│ └────┴────┴────┴────┴────┘        │
│ 1/6 수 · 6곳 · 걷기 약 2시간        │ 보조 한 줄(상태 글자색: 넘치면)
│ ┌────────────────────────────┐   │
│ │ 지금 갈 곳                      │   │ 오늘 날짜일 때만, 한 줄 카드
│ │ 1NCE            [길 안내]      │   │ (검정 단추 = 화면의 주 단추)
│ └────────────────────────────┘   │
│ (1)  1NCE                 [봤다]  │ 줄(0.1): 번호 · 이름 · 보조 · 단추
│      노스 홀 · 14731 · 10:20쯤     │
│ (2)  a.cure               [봤다]  │
│      베네시안 G · 63401 · 10:50쯤  │
│ (3)  ...                          │
│ ──                                │
│ 부스 자리는 짐작이다 (11/22 확인)   │ 묶음 아래 한 줄 (줄마다 안 붙인다)
├──────────────────────────────────┤
│  지도    [동선]    일기    설정     │ 탭 (가려지지 않는다)
└──────────────────────────────────┘
```

- 날짜 칩 한 줄이 맨 위에 **붙어 있다**(스크롤해도 남는다). 고른 칩만 검정 칠한 면. 칩 아래 "n곳".
- 줄 번호 원은 지도의 동선 번호와 **같은 번호 · 같은 농도**(날짜별 강조색 단계)다. 번호가 곧 지도와 이어지는 끈이다.
- 줄의 주 단추는 "봤다"(체크 아이콘 단추 44px 한 개, 누르면 줄이 연해지고 다음 갈 곳이 올라온다). 길찾기는 "지금 갈 곳" 카드와 카드(아래 ②)에 있다.
- "차례 정리"(글자 단추)를 누르면 카드 한 장이 열려 **날짜 채우기 · 걷는 차례로 · 하루에 볼 곳(칩: 정하지 않음 · 5 · 8 · 10 · 12 · 15 · 20) · 나누기(링크 · 코드 · 글 · 파일) · 받은 목록 넣기**를 한곳에 둔다. 지금 아래에 떠 있는 도크를 없애는 대신 한 번 쓰는 동작을 여기로 옮기는 것이다(숨기는 층이 아니다: 핵심 동작인 봤다 · 길찾기는 줄에 그대로 있다).

### 화면 틀 ②: 줄을 누르면 열리는 회사 카드 ("회사 카드 크게")

지도의 카드와 **같은 카드**다.

```
┌──────────────────────────────────┐
│            ━━━                    │ 손잡이 (아래로 끌면 닫힘)
│ 1NCE                              │ 24px
│ 부스 14731 · 노스 홀  [자리 짐작]   │ 14px + 표시 하나
│ IoT·센서 · 스마트 도시              │ 분야 한 줄
│ ┌────────────────────────────┐   │
│ │          길 안내 시작            │   │ 검정 단추 52px
│ └────────────────────────────┘   │
│ 지도에서 보기   일기 쓰기           │ 글자 단추 둘
│ 날짜  [1/6][1/7][1/8][1/9]         │ 칩(고른 날짜만 검정)
│ 차례  [위로][아래로]               │
│ 관심 빼기      명함 이벤트 표시     │ 글자 단추 (빼기는 위험 글자색 아님, 되돌릴 수 있다)
└──────────────────────────────────┘
```

- 날짜는 줄 안의 선택 상자(`select`)가 아니라 **칩 네 개**(폰의 선택 상자는 크고 한 번 더 눌러야 한다).
- "위로 · 아래로"는 카드 안에 둔다. 끌어서 순서 바꾸기는 하지 않는다(스크롤과 부딪친다).
- 관심에서 빼면 되돌리기 한 줄("되돌리기", 5초)을 띄운다.

### 화면 틀 ③: 비었을 때

```
│ 동선                              │
│ 관심 회사를 고르면 동선이 생긴다.   │ 한 줄
│ ┌────────────────────────────┐   │
│ │      지도에서 회사 찾기          │   │ 검정 단추
│ └────────────────────────────┘   │
```

날짜 칩의 "0곳"은 연한 글자로 둔다(누르면 빈 날 화면).

### 꼭 있을 것

- 날짜 칩 한 줄(고정) + 칩마다 곳 수.
- 줄 하나 = 번호 · 이름 · 보조 한 줄 · 단추 하나. 줄 번호 = 지도 번호.
- 지금 갈 곳은 한 줄 카드 하나(오늘 날짜일 때만). 지도로 · 길 안내는 카드와 줄 카드에서.
- 회사 카드 = 지도 카드와 같은 카드 + 날짜 칩 + 위로 · 아래로 · 빼기 · 일기 쓰기.
- 하루가 넘칠 때 "n곳이 넘친다"(상태 글자색) 한 줄과 "날짜 옮기기" 길(카드의 날짜 칩).
- 비었다 · 불러오는 중 · 못 불러옴 화면(`frame.js`).

### 뺄 것

- 줄 안의 날짜 선택 상자 · 위로 · 아래로 · 빼기 · 명함 이벤트 · 일기 단추 → 카드로.
- 줄마다 "(자리는 짐작)" · "내 일정" 같은 되풀이 글 → 묶음 아래 한 줄로.
- 큰 제목(34px) + 두 줄 안내 → 제목 한 줄(24px) + 안내는 묶음 아래로.
- "종이 명함이 있나요?" 큰 카드(지금 위쪽 130px 차지) → 답하면 사라지는 한 줄 띠(높이 48: "종이 명함이 있나요? [있다] [없다]"). 처음 들어올 때와 출발 8일 전 두 번만(R22).
- 동선 화면 아래의 도크(날짜 채우기 · 걷는 차례로).

### 공식 앱에서 배운 점

- 일정 화면은 **날짜 띠 하나를 맨 위에 두고**(요일 + 날짜 숫자, 고른 날은 원으로 채움) 그 아래 "일정 / 내 일정" 두 칸, 그 아래 칩(거르기 · 추천 · 주요)이 붙는다. 순서가 "언제 → 무엇 → 거르기"다. 우리 동선도 "언제(날짜 칩) → 무엇(줄) → 정리(차례 정리)"로 맞춘다.
- 줄 하나는 때 · 제목 · 곳(건물, 층, 방) · 단추 한 개 · 알람 아이콘 하나로 끝난다. 단추가 많지 않다.
- 추천 줄은 연한 면 + 까닭 한 줄("비슷한 관심의 사람들이 많이 담았다")로 구별한다. 우리는 서버가 없어 "사람들이 많이 담음"은 못 하고, 까닭을 공식 자료로만 적는다(혁신상 · 한국 기업 · 내 분야, R20).
- 공식 앱의 소개 글은 "관심 부스 목록으로 가장 빠른 길을 만든다"고 말한다. 우리 "걷는 차례로"가 같은 일이다. 공식 앱이 안에서 얼마나 정확한지는 못 봤다.

### 우리가 다르게 할 점

- 공식 앱의 줄 단추(약 33px 높이)는 44px 아래다. 우리는 줄 단추 44px 이상.
- 공식 앱은 보라 · 남색 · 연두 · 파랑을 한 화면에 섞는다. 우리는 회색 단계 + 강조색 하나(날짜 번호 농도).
- 공식 앱의 일정은 로그인으로 웹 일정과 맞춘다(서버). 우리는 폰에만 둔다. 그래서 "공유"는 링크 · 코드 · 파일(나누기 카드)이다.
- 공식 앱은 한 날에 몇 곳이 넘치는지 말해 주지 않는 것으로 보인다(못 확인). 우리는 시간 안에 들어가는 곳 수를 말해 준다(R18).
- 공식 일정은 1/5(화)부터 보인다(스토어 그림 기준, 사전 행사로 보인다). 우리 날짜 칩은 1/6 ~ 1/9 + 미정이다. 세션을 "내 일정"에 넣을 때 1/5 세션이 어디로 가는지 5단계에서 확인한다.

### 5단계 끝난 모습 (작업.md 연결)

- 날짜 칩의 곳 수 합 = 관심 회사 수. 줄 번호 = 지도 번호. 360px에서 줄 단추가 하나(+ 카드). 도크와 탭이 겹치지 않는다. 사진: 동선 · 카드 · 빈 화면 · 넘침 경고.

### 단계마다 꼭 반영할 것 (5단계 세 줄)

1. **줄 하나에 단추 하나**: 날짜 · 위로 · 아래로 · 빼기 · 명함 이벤트 · 일기는 줄을 누르면 열리는 회사 카드(지도 카드와 같은 틀)로 옮긴다.
2. **날짜 칩 한 줄을 맨 위에 붙이고**, 칩 아래에 곳 수. 지도 번호와 같은 번호 · 같은 농도.
3. **도크 · 큰 제목 · 종이 명함 큰 카드를 걷어** 처음 보이는 한 화면에 날짜 칩 + 지금 갈 곳 + 줄 둘이 보이게.

## 6단계 일기 + 만난 사람 — 첫 칸에서 누구를 만났는지 바로 보인다

**한 줄:** 일기 탭을 열면 맨 위에 "만난 사람"이 보이고, 그 아래 회사 일기가 날짜별로 이어진다. 듣기 · 대화 칸은 회사 일기 안으로 들어간다.

지금 일기 화면(`web/views/diary.js`)의 문제: 맨 위에 큰 제목과 회색 단추 셋(듣기 · 대화 칸 · 만난 사람)이 있어 "만난 사람"이 두 번 눌러야 닿고, 그 아래 "보내기" 묶음(두 줄 설명 + 단추 둘)이 일기 목록보다 먼저 나온다. 목록은 세 번째 묶음부터 시작한다(`후-light-diary.png`).

### 화면 틀 ①: 일기 (360px)

```
┌──────────────────────────────────┐
│ [아이콘] 글로벌 어학연수 [비공식]   │
├──────────────────────────────────┤
│ 일기                              │ 제목 24px
│ 만난 사람 3명            명함 받기  │ 묶음 제목 18px + 글자 단추(카메라)
│ ┌────────────────────────────┐   │
│ │ (재)  재엽 · 학생          [↗]  │   │ 줄: 이니셜 원 · 이름 · 아이콘 단추
│ │       1NCE · 14731 · 10:20     │   │ 보조 한 줄: 회사 · 부스 · 때
│ │ (민)  민수 ...             [↗]  │   │ ↗ = 가장 먼저 읽은 연락처 열기
│ │ (수)  수아 ...             [↗]  │   │
│ │ 전체 3명 ›                      │   │ 글자 단추
│ └────────────────────────────┘   │
│ 이 폰에만 남는다. 일기와 함께 가지 않는다. │ 한 줄 (묶음 아래)
│                                   │
│ 1/6 수 · 일기 2개                  │ 날짜 묶음 제목
│ ┌────────────────────────────┐   │
│ │ 1NCE  [학생]          보냄 ✓    │   │ 회사 · 태그 칩 · 보낸 표시
│ │ 로봇 팔이 컵을 집는 시연을 봤다  │   │ 본 것 한 줄 (말줄임)
│ └────────────────────────────┘   │
│ 보내지 않은 일기 1개    [보내기]    │ 한 줄 띠(설명은 카드 안에서)
│ ┌────────────────────────────┐   │
│ │          일기 쓰기              │   │ 검정 단추 52px, 탭 바로 위
│ └────────────────────────────┘   │
├──────────────────────────────────┤
│  지도     동선    [일기]    설정    │
└──────────────────────────────────┘
```

- "만난 사람"은 **첫 묶음**, 최근 순 세 명. 줄을 누르면 카드(0.3)가 열려 연락처 전부(깃허브 · 디스코드 · 링크드인 · 웹 한 줄씩) · 메모 · 만난 곳 · 그 회사 일기 쓰기 · 고치기 · 지우기가 나온다.
- 일기 줄을 누르면 일기 카드가 열린다(본 것 · 느낀 점 · 네 태그 · 대화 · 고치기).
- "일기 쓰기"가 이 화면의 **하나뿐인 검정 단추**다. "남의 명함 받기"는 만난 사람 묶음 머리의 글자 단추다(현장에서 빈도는 일기가 더 높다).

### 화면 틀 ②: 남의 명함 받기 — 카메라 한 번에 줄이 생긴다

```
│ ← 남의 명함 받기                   │
│ ┌────────────────────────────┐   │
│ │         [ 카메라 영역 ]          │   │ QR 가운데 맞추기 (누를 때만 켠다)
│ └────────────────────────────┘   │
│ 읽으면 바로 폰에 남는다.            │ 한 줄
│ 카메라가 안 되면  주소 붙여넣기 ›   │ 글자 단추
```

- 읽자마자 **저장**하고 "이름 적기" 카드를 연다(이름은 비워도 저장된다 → 목록에 "이름 없음 · 방금"). 지금처럼 읽은 주소 → 이 사람 → 폰에 남기기 세 구획을 지나지 않는다.
- 같은 사람을 다시 읽으면 새 줄이 아니라 "이미 있다 · 열기".

### 화면 틀 ③: 일기 쓰기

```
│ ← 일기 쓰기                        │
│ 회사   1NCE ▾  (동선에서 오면 미리 채움)│
│ 본 것  ┌──────────────────────┐    │ 이 칸만 있으면 저장된다
│        └──────────────────────┘    │
│ 느낀 점 ┌──────────────────────┐    │ 선택
│ 누구에게 [학생][취준생][정년][장년]   │ 칩, 마지막에 고른 것을 기억
│ 대화    [듣기]  [붙여넣기]          │ 글자 단추 둘 (R26 · R40 · R41)
│ ┌────────────────────────────┐   │
│ │            저장                 │   │ 검정 단추 52px
```

- 부스 앞에서 10초 안에 끝나야 한다: **필수는 "본 것" 한 칸**. 날짜는 오늘로 자동, 회사는 동선의 "일기 쓰기"에서 오면 미리 채운다.
- 적던 글은 폰에 남겨 앱을 닫아도 돌아온다(보내기 전까지).
- 듣기 · 대화 칸 · 붙여넣기는 이 화면 안의 **회사 일기 일부**다. 일기 탭 맨 위에 따로 단추를 두지 않는다.

### 꼭 있을 것

- 첫 묶음 = 만난 사람(최근 세 명 + 전체 보기 + 명함 받기).
- 만난 사람 줄: 이니셜 원 · 이름 · 회사 · 부스 · 때 · 연락처 열기 아이콘. 전체 화면에는 이름 · 회사 찾기 칸 하나.
- 일기 줄: 회사 · 태그 · 본 것 한 줄 · 보냄 표시. 날짜 묶음.
- 보내지 않은 수와 "보내기"가 한 줄 띠. 보내기는 파일로 내려오고(11/21 정함) 누르면 한 줄로 "파일이 내려왔다. 이 파일을 정리하는 사람에게 건넨다".
- 비었을 때: "만난 사람 0명 — 남의 명함 받기", "일기 0개 — 일기 쓰기" 각각 한 줄 + 단추.

### 뺄 것

- 맨 위 회색 단추 셋(듣기 · 대화 칸 · 만난 사람).
- 큰 "보내기" 묶음(제목 + 설명 두 줄 + 단추 둘) → 한 줄 띠.
- 일기 날짜 묶음 제목의 "· 1개" 같은 군더더기(묶음 제목은 날짜 하나).
- 남의 명함 받기의 구획 넷(카메라 / 손으로 / 읽은 주소 / 이 사람) → 카메라 한 칸 + "주소 붙여넣기" 글자 단추.
- 줄마다 "지우기 · 고치기" 단추 → 카드 안.

### 공식 앱에서 배운 점

- 공식 앱의 사람 만나기(Attendee Connect)는 **배지의 QR을 열거나 상대 것을 스캔하면 끝나는 것**을 핵심으로 소개한다(상대에게 수락을 받는 단계가 있고, QR은 계속 바뀐다는 설명). 스캔 한 번 = 연락처 한 줄이다. 우리도 읽는 즉시 저장한다.
- 공식 앱은 즐겨찾은 전시사 · 연사를 사이드 메뉴에 **고정**한다는 설명이 있다. 자주 보는 것을 맨 위에 두는 같은 생각이다 → 우리는 만난 사람을 일기 첫 칸에 둔다.
- 공식 앱에서 일기 · 메모 기능은 소개 글과 스토어 그림에서 **찾지 못했다**(앱 안은 못 봄). 일기는 이 앱만의 것이다.

### 우리가 다르게 할 점

- 서버 · 계정이 없으므로 수락 · 거절이 없고, 상대 앱에 알림이 가지 않는다. 읽은 연락처는 이 폰에만 남고 일기 보내기 파일에 들어가지 않는다(지금 규칙 그대로).
- 우리 QR은 고정 QR(깃허브 · 디스코드 주소)이다. 바뀌는 QR이 아니다.
- 공식 앱은 연락처를 앱 안 메시지로 이어 주지만 우리는 **상대의 주소를 열어 줄 뿐**이다(깃허브 · 디스코드 · 웹 링크로 나간다).

### 6단계 끝난 모습 (작업.md 연결)

- 일기 탭을 열면 첫 묶음에서 누구를 만났는지가 보인다. 카메라로 읽자마자 목록에 줄이 생긴다. 일기는 한 칸만 적어도 저장된다. 360px 사진: 일기 · 만난 사람 카드 · 명함 받기 · 일기 쓰기 · 비었을 때.

### 단계마다 꼭 반영할 것 (6단계 세 줄)

1. **일기 첫 묶음 = 만난 사람 세 명 + "명함 받기"**. 맨 위 회색 단추 셋은 없앤다(듣기 · 대화 칸은 회사 일기 안으로).
2. **카메라로 읽으면 바로 저장**(이름은 나중에 적어도 된다). 같은 사람은 다시 만들지 않는다.
3. **일기는 "본 것" 한 칸만 적어도 저장**되고, 검정 단추 하나(저장 · 일기 쓰기)가 탭 위에 있으며 보내기는 한 줄 띠다.

## 7단계 설정 + 글자 크기 — 한 줄에 하나, 글자 크기가 맨 위

**한 줄:** 설정은 "이름 왼쪽 · 상태 또는 단추 오른쪽" 한 줄 목록으로 줄이고, 맨 위에 글자 크기 네 단계를 둔다.

지금 설정 화면(`web/views/settings.js`)의 문제: 묶음마다 제목 + 설명 두세 줄 + 단추가 있어 알림 한 묶음이 폰 첫 화면의 절반을 차지한다. 화면 색은 칩이 있어 괜찮다(`후-light-settings.png`).

### 화면 틀: 설정 (360px)

```
┌──────────────────────────────────┐
│ 설정                              │ 제목 24px
│ 글자 크기                          │ 묶음 제목 18px
│ [기본] [크게] [더 크게] [가장 크게]   │ 칩 넷(칸 균등), 고른 것 검정
│ ┌────────────────────────────┐   │
│ │ 1NCE · 노스 홀 · 부스 14731     │   │ 미리 보기: 고르면 바로 바뀐다
│ └────────────────────────────┘   │
│ 화면 색      [자동] [밝게] [어둡게]  │
│ ──────────────────────────────── │
│ 명함       재엽 · 학생     QR 보기 ›│ 한 줄(56px): 이름 · 상태 · 단추
│ 알림       꺼짐              켜기   │
│ 인터넷 없이  준비됨 · 12MB   비우기  │
│ 내보내기    일기 · 대화 3개   파일로  │
│ 자료       11/21 받음 · 출처 ›     │
│ 이 폰의 내 자료 지우기 ›            │ 글자 단추(되돌릴 수 없다, 확인 둘)
├──────────────────────────────────┤
│  지도     동선     일기    [설정]    │
└──────────────────────────────────┘
```

- 한 줄은 **높이 56px** 이상, 줄 전체가 눌린다. 오른쪽에 상태 글자 또는 글자 단추 하나.
- 설명은 줄 아래에 **상태가 문제일 때만** 한 줄(예: 알림이 꺼져 있고 아이폰이면 "홈 화면에 추가한 뒤에 켤 수 있다."). 평소 설명 문단은 없다.
- "자료"를 누르면 카드가 열려 받은 날짜 · 출처 · 부스 자리가 짐작이라는 안내를 보인다(자료 출처와 받은 날짜를 늘 보인다는 규칙).
- "이 폰의 내 자료 지우기"는 비공개 전환(1/31 안) 뒤 폰을 정리하는 길이다. 먼저 내보내기를 권하고 확인을 두 번 받는다. **정할 것**으로 남긴다(주인이 넣을지 고른다).

### 글자 크기 네 단계 (구체)

| 단계 | 배율 | 본문 | 줄 보조 글자 | 제목(상한) |
|---|---|---|---|---|
| 기본 | 100% | 16px | 14px | 24px |
| 크게 | 115% | 18px | 16px | 26px |
| 더 크게 | 130% | 21px | 18px | 28px |
| 가장 크게 | 150% | 24px | 21px | 30px |

- 구현 방향: `tokens.css`에 `--scale` 하나를 두고 `--fs-*`를 `calc(Npx * var(--scale))`로 바꾼다. 단계는 `<html data-text="1|2|3|4">`로 걸고, **첫 그림 전에** 적용한다(`theme.js`가 테마에 하는 것과 같은 방식, 깜빡임 없게). 폰에만 저장한다.
- 제목은 배율을 다 받지 않는다(상한). 큰 제목이 360px에서 두 줄로 넘치는 것을 막는다.
- 누르는 곳은 글자가 커질수록 같이 커지되(줄 높이는 내용 따라) 줄어들지는 않는다(44px 아래로 안 간다).
- 지도 안 글자(부스 이름 · 홀 이름)는 최대 130%까지만 키우고, 겹치면 지금처럼 중요한 것부터 남기고 숨긴다(지도 글자는 캔버스라 따로 읽는다 — `web/tokens.js`).
- 줄의 보조 글자 한 줄은 큰 단계에서 **두 줄까지 줄바꿈**을 허용한다(말줄임을 풀지 않으면 읽을 수 없다).
- 칩 한 줄은 가로 스크롤을 지키되 **글자 크기 칩 넷**은 한 줄에 다 보여야 하므로 큰 단계에서는 2 × 2로 접는다(이 칩만).
- 아래 탭 이름은 단계가 커져도 두 글자 이름이 칸(약 90px)에 들어가는 한 최대 16px까지만 키운다.
- 시험: 네 단계 × (360 · 390px) × 화면 여섯(지도 · 동선 · 일기 · 설정 · 명함 · 회사 카드)에서 **가로 넘침 0 · 글자 잘림 0 · 탭이 안 가림**. 지금 `scripts/browser-*.mjs`의 360px 시험에 단계를 도는 반복을 더한다.

### 꼭 있을 것

- 글자 크기 네 칩 + 미리 보기 한 줄(고르면 바로 모든 화면에 적용, 폰에 남음).
- 화면 색 · 명함(QR 보기 · 고치기) · 알림(켜기 · 꺼짐 상태) · 인터넷 없이(준비됨 · 저장 크기 · 저장 공간 비우기) · 내보내기 · 자료.
- 번역 모델이 남긴 캐시(약 250MB)를 비우는 "저장 공간 비우기"(1단계에서 7단계로 미룬 것).
- 알림 · 위치 · 카메라 권한이 막혔을 때 "왜 안 되는지 + 어디서 켜는지" 한 줄.

### 뺄 것

- 묶음마다 제목 + 설명 문단. 상태 문장 두세 줄 → 한 줄 상태.
- "홈 화면에 추가"를 설정 첫 화면의 큰 단추로 두는 것 → 안 되어 있을 때만 "인터넷 없이" 줄에 상태로.
- 명함 이름 옆 태그 칩 + 단추 둘 → 한 줄(이름 · 태그 · "QR 보기 ›")과 카드의 "명함 고치기".

### 공식 앱에서 배운 점

- 공식 앱의 **설정 화면은 보지 못했다**(스토어 그림과 소개 글에 없음). 근거 없이 흉내 내지 않는다.
- 스토어 그림에서 읽은 글자: 제목 약 17px · 줄 보조 14px · 이유 한 줄 12px. 12px 글자가 줄마다 있다. 우리 기본 단계는 이보다 작은 글자를 쓰지 않는다(8단계 목록 15번).
- 공식 앱은 큰 글자 단계를 소개 글 어디에도 말하지 않는다(폰 시스템 설정을 따르는지 **못 봄**). 우리는 앱 안에 눈에 보이는 단계를 둔다.

### 우리가 다르게 할 점

- 계정 · 로그아웃 · 언어 · 알림 종류 선택은 없다(서버 · 계정이 없다). 있는 것은 이 폰 안의 것뿐이다.
- 글자 크기를 설정 맨 위에 둔다. 현장에서 한 손 · 햇빛 아래 읽는 일이 먼저이기 때문이다.
- "자동(폰 설정 따름)" 글자 단계는 두지 않는다: 설치한 웹앱은 폰의 글자 크기 설정을 안정적으로 읽지 못한다(정할 것에 적는다).

### 7단계 끝난 모습 (작업.md 연결)

- 글자 크기를 네 단계로 바꾸면 지도 · 동선 · 일기 · 설정 · 명함 · 카드에 적용되고 폰에 남는다. 가장 큰 단계에서도 360px 가로 넘침 0. 사진: 네 단계 × 설정 · 동선(두 화면) = 열두 장.

### 단계마다 꼭 반영할 것 (7단계 세 줄)

1. **글자 크기 네 칩 + 미리 보기를 설정 맨 위에.** 단계는 첫 그림 전에 걸고 폰에 남긴다.
2. **`--fs-*`를 배율로** 바꾸되 제목은 상한, 지도 글자는 130%까지, 줄 보조 글자는 큰 단계에서 두 줄 허용.
3. **설정을 한 줄 목록(56px)으로** 줄이고 설명 문단을 걷으며, "저장 공간 비우기"와 권한이 막혔을 때의 한 줄 안내를 넣는다.

## 8단계 디자인 마감 — 네 탭을 한 틀로

**한 줄:** 네 탭이 같은 머리 · 같은 제목 · 같은 줄 · 같은 카드 · 같은 주 단추 자리를 쓰는지 표로 맞추고, 전후 폰 사진과 글자 수 표를 남긴다.

### 맞출 것 (네 탭 × 항목 표)

| 항목 | 규칙 | 지도 | 동선 | 일기 | 설정 |
|---|---|---|---|---|---|
| 머리(아이콘 · 이름 · 비공식) | 높이 같음, 스크롤하면 올라감(지도는 찾기 칸에 합침) | | | | |
| 제목 | 24px 한 줄, 탭 이름과 겹치면 뺀다 | | | | |
| 주 단추 | 검정 하나, 탭 바로 위 52px 또는 줄 안 | | | | |
| 줄 | 0.1의 꼴 | | | | |
| 카드 | 0.3의 한 종류 | | | | |
| 비었다 · 불러오는 중 · 못 불러옴 | `frame.js` | | | | |
| 간격 · 모서리 | `--s*` · `--radius*`만 | | | | |

(빈칸은 8단계에서 확인해 ○ / × 와 고친 곳을 적는다.)

### 전후 폰 사진

- 같은 기기 틀(360 × 740)로, 밝게와 어둡게 둘 다. 화면: 처음 명함 · QR · 지도(캠퍼스 · 홀 · 부스) · 회사 카드 · 동선 · 동선 카드 · 일기 · 만난 사람 카드 · 일기 쓰기 · 설정 · 빈 화면 · 글자 크기 가장 큼. 이름은 `docs/screens/8x-전-…` / `8x-후-…`.
- "전"은 5단계 시작 때 main의 모습(아래 "8단계에서 고칠 것"을 가리키는 사진)이고, 70 ~ 73 · 80 ~ 83은 파스텔 때 사진이라 쓰지 않는다.

### 글자 수 다시 세기

- 화면마다 **처음 보이는 한 화면**(360 × 740, 스크롤 전)의 글자 수를 브라우저 시험에서 센다(`innerText`의 공백 뺀 글자 수, 제목 · 단추 글자 · 줄 글자와 설명 글을 나누어). 전 · 후 표를 `작업.md` 8단계에 붙인다.
- 제안 상한(정할 것): 처음 보이는 한 화면의 설명 글 **60자 이하**, 한 묶음의 설명 **두 문장 이하**. 지금 값은 표에서 처음 센다.

### 공식 앱에서 배운 점

- 공식 앱은 **화면마다 같은 머리**(남색 띠 + 왼쪽 메뉴 또는 뒤로 + 가운데 제목 + 오른쪽 검색)를 쓴다. 어느 화면에 가도 위쪽이 같다. 우리 네 탭도 머리 높이 · 아이콘 · 제목 위치를 맞춘다.
- 공식 앱은 한 화면에 쓰이는 색이 많다(보라 띠 · 파랑 단추 · 연두 단추 · 남색 타일 · 시작 화면의 붉은 판). 같은 보라가 날짜 띠와 타일과 홈 위쪽에 모두 쓰여 **색이 한 가지 뜻을 갖지 못한다**. 우리는 강조색 하나가 "관심 · 동선 · 지금 위치 · 고른 것"이라는 뜻을 끝까지 지킨다.
- 공식 앱 홈은 인사 + 큰 단추 하나(일정 보기) + 바로 가기 둘 + 추천 한 줄 가로 카드다. "주 단추 하나"는 배울 만하다. 우리는 홈이 없고 지도가 첫 화면이다.

### 우리가 다르게 할 점

- 시작 화면(스플래시)을 두지 않는다(첫 화면 2초).
- 햄버거 메뉴를 두지 않는다. 아래 탭 넷이고 숨기는 층이 없다.
- 그림 · 사진 · 그라데이션을 쓰지 않는다. 회색 단계와 강조색 하나뿐이다.

### 8단계에서 고칠 것 (이미 끝난 2 ~ 4단계에서 사진으로 본 것)

근거는 `docs/screens`의 사진이다. **코드로 한 번 더 확인한 뒤 고친다**(사진만 본 것도 있다).

**2단계 틀**

1. 머리 줄(아이콘 · 이름 · 비공식)이 모든 탭 맨 위에서 약 60px를 쓴다. 지도에서는 찾기 칸 · 홀 칩과 겹쳐 지도 칸이 좁아진다 → 지도에서는 머리를 줄이거나 찾기 칸에 합친다.
2. 도크(주 단추 막대)와 탭 막대가 두 겹으로 아래 약 120px를 쓴다. 동선 · 일기 · 명함 만들기에서 마지막 줄 · 입력칸이 가려진다(`무채색-테마/후-light-plan.png`의 "하루에 볼 것", `80-first-open.png`의 아이디 칸). → 도크를 걷고 주 단추를 내용 끝 또는 탭 바로 위 하나로, 가려지는 높이만큼 아래 여백을 둔다.
3. 큰 제목(34px)이 동선 · 일기 · 설정 맨 위에서 화면의 약 4분의 1을 쓰고 탭 이름과 겹친다 → 24px 한 줄.
4. 지금 탭 표시가 회색 알약 + 굵은 글자뿐이고 아이콘 모양은 같다 → 선택된 아이콘을 굵은 선으로(색이 아닌 모양으로 구별).
5. 단추 모양이 셋이다: 검정 칠한 단추 · 밑줄 글자 · 회색 면 단추(일기 맨 위 · 칩과 구별이 안 됨). `design.md`는 둘만 허용한다 → 회색 면 단추를 없앤다.

**3단계 첫 실행 명함**

6. 필수는 둘(별명 · 나)인데 선택 칸(한 줄 · 깃허브 · 디스코드)이 처음 화면에 다 보여 스크롤이 길고, "명함 만들기" 도크가 입력칸을 가린다 → 필수 둘 + 만들기 단추가 스크롤 없이 한 화면에 들어오게 하고 선택 칸은 그 아래로.
7. QR 화면 아래에 "종이 명함이 있나요?" 묶음과 날짜 칸이 같이 있다. 같은 질문이 동선에도 있어 **같은 것을 두 곳에 두지 않는다**는 규칙과 어긋난다 → QR 화면은 QR + "지도로"만, 종이 명함 질문은 5단계의 동선 띠 한 곳(R22)과 설정에서만.
8. 70 ~ 73 · 80 ~ 83 사진은 파스텔 때 모습이다 → 8단계 전후 사진에서 새로 찍는다.

**4단계 지도**

9. 홀 칩 한 줄이 찾기 칸 바로 아래 지도 위에 떠서 부스 이름 글자를 덮는다(`후-light-map-card.png`) → 칩 줄에 바탕 면을 주거나 지도 칸을 칩 아래에서 시작하게.
10. 회사 카드가 열려 있을 때 카드 아래로 "지도 보기" 묶음이 같이 비친다 → 카드가 열리면 그 묶음을 가리고 카드가 탭 바로 위까지 닿게.

**모든 단계 공통**

11. 12px 글자(출처 · 메모 · 가장 작은 글)가 곳곳에 쓰인다 → 기본 단계에서 13px 이상으로 올릴지 센 뒤 정한다(7단계 글자 크기와 같이).
12. 어둡게 판 사진이 전후 둘 다 있는지 확인한다(밝게만 있으면 어둡게를 더 찍는다).

### 8단계 끝난 모습 (작업.md 연결)

- 위 맞출 것 표가 모두 ○. 전후 사진 열두 화면 × 밝게 · 어둡게. 글자 수 전 · 후 표. `scripts/smoke.mjs` · 360px 브라우저 시험 · 보드 check 통과.

### 단계마다 꼭 반영할 것 (8단계 세 줄)

1. **네 탭의 머리 · 제목 · 주 단추 · 줄 · 카드를 표로 맞추고** 도크(두 겹 막대)를 걷는다.
2. **단추는 검정 하나 + 글자 단추**만 남기고(회색 면 단추 삭제), 강조색은 "관심 · 동선 · 지금 위치 · 고른 것"에만 쓴다.
3. **전후 사진(밝게 · 어둡게)과 글자 수 표**를 남기고, 12px 글자를 센 뒤 정한다.

## 끝난 단계 한 장씩 (참고)

### 첫 실행 명함 (3단계, 끝)

```
처음 들어옴
┌──────────────────────────────────┐
│ 환영한다. CES 2027 준비 지도다.     │ 한 줄
│ 명함부터 만든다                     │ 제목
│ 별명  [____________]               │ 필수
│ 나    [학생][취준생][정년][장년]     │ 필수, 칸 56px 2 × 2
│ 한 줄 · 깃허브 · 디스코드 (선택)     │ 선택 (8단계 목록 6번)
│ [명함 만들기]  [나중에]             │
└──────────────────────────────────┘
만든 뒤: 명함 + QR 둘 + [지도로] + 명함 고치기
```

- 공식 앱에서 배운 점: 공식 앱은 로그인이 필요하고 처음 화면에 큰 시작 문구와 로그인이 온다고 소개한다(앱 안은 못 봄). 처음 한 번의 가벼움이 중요하다는 점은 같다.
- 우리가 다르게: 로그인 없음, 필수 둘, 폰에만 저장, 처음에도 "나중에".

### 지도 탭 (4단계, 끝)

```
┌──────────────────────────────────┐
│ [   회사 · 부스 번호 · 홀 찾기   ] │ 찾기 칸
│ [전체][웨스트][센트럴][노스][사우스] │ 홀 칩
│ ┌────────────────────────┬───┐   │
│ │   지도 (두 손가락 확대)   │ + │   │ 오른쪽 세로 단추 + − 내 위치 3D
│ │   확대 3단계: 캠퍼스 → 홀 → 부스 │ − │   │
│ └────────────────────────┴───┘   │
│ ━━━ 회사 카드(눌렀을 때 올라옴)      │
├──────────────────────────────────┤
```

- 공식 앱에서 배운 점: 지도 안에서 부스를 누르면 회사 정보 · 사진 · 링크 · 길 안내가 한 번에 뜬다는 소개(확인한 것은 소개 글뿐, 지도 화면은 못 봄). 우리 카드가 같은 일을 한다.
- 우리가 다르게: 부스 자리가 정식 배치도 전이라 짐작이고 "자리 짐작"을 카드마다 보인다. 층별 3D는 하지 않는다(공식 앱은 건물 층을 나누어 보인다는 소개).
