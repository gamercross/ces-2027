# 물어볼 말 · 듣기

## 쓰는 법

1. 첫 화면의 "부스에서" 칸이나 회사 줄의 "듣기"로 들어간다. 이 화면들은 누를 때 불러온다.
2. **물어볼 말** (`#/ask`): 묶음(인사 · 제품 · 가격 · 출시 · 한국 판매 · 채용 · 명함 교환 · 이벤트)에서 한국어 질문을 고르면 영어가 보인다. "크게 띄우기"로 상대에게 보여 주거나 "읽어 주기"로 읽어 준다. 묶음은 미리 옮겨 둔 자료(`data/phrases.json`)라 인터넷 없이도 된다.
3. **듣기** (`#/listen/<회사>`): 먼저 "녹음해도 될까요?"를 영어로 크게 띄워 알린다. 처음 한 번은 "상대에게 알렸나요?"를 묻는다. 듣는 동안 줄마다 영어와 한국어가 보이고, 멈추면 그 회사의 일기 초안이 된다.
4. **일기 초안**: 날짜 · 회사 · "본 것"(들은 글의 앞부분) · 들은 글(원문 · 번역)이 들어 있다. 느낀 점과 "누구에게"는 비어 있다. 다듬어 남기기 전에는 보내지 않는다.

받아쓰기가 안 되는 폰에서는 "손으로 적기"에 적은 줄로 같은 초안을 만든다.

## 폰 밖으로 나가는 것

- 기본 길(폰 안에서만)에서는 소리도 글도 폰 밖으로 나가지 않는다.
- 녹음은 폰 안(IndexedDB)에, 들은 글은 일기와 같이 폰 안에 남는다. 보내기를 눌러도 들은 글과 녹음은 가지 않는다(보내는 묶음에 그 칸이 없다).
- 키도 서버도 쓰지 않는다.

## 두 길 (쓰는 사람이 화면에서 고른다)

11/21에 정했다: 두 길을 다 두고, "물어볼 말"과 "듣기" 화면의 "받아쓰기 · 번역을 어디서 하나"에서 쓰는 사람이 고른다. 고른 것은 폰에만 남는다. 폰의 음성 인식 서비스를 처음 고를 때는 "인터넷이 필요하고 소리가 구글 · 애플로 간다"를 한 줄로 보이고 한 번 확인받는다. 확인하지 않으면 폰 안에서만으로 남는다. 어느 길이든 키와 우리 서버는 쓰지 않는다. 고르기 전의 기본값은 `config/settings.json`의 `speech`다.

| 값 | 뜻 | 받아쓰기 | 번역 |
|---|---|---|---|
| `on-device` (기본) | 폰 안에서만 | 폰이 "폰 안에서 받아 적기"를 도울 때만 된다. 아니면 "이 폰에서는 안 됨" | 폰 안의 번역기가 있을 때만 된다 |
| `device-service` | 폰의 음성 인식 서비스 | 된다. 인터넷이 있어야 하고 소리가 구글(안드로이드 크롬)이나 애플(아이폰)로 간다 | 폰 안의 번역기가 없으면 "번역 사이트에서 열기" 링크가 보인다(적은 글이 구글 번역으로 간다) |


## 되는 폰 · 안 되는 폰

**실제 폰에서 확인한 것이 아니다.** 브라우저 문서로 아는 것을 적었고, 화면은 폰 크기의 시험 브라우저에서 기능을 꾸며 넣어 확인했다. 팀 시험 때 이 표를 폰으로 채운다. 앱은 폰에 직접 물어보고 그 답대로 "됨 / 이 폰에서는 안 됨"을 보이므로, 표가 틀려도 화면은 폰의 답을 따른다.

| 기능 | 길 | 안드로이드 크롬 | 아이폰 사파리 |
|---|---|---|---|
| 질문 묶음 · 크게 띄우기 | 둘 다 | 됨 (오프라인도) | 됨 (오프라인도) |
| 읽어 주기 | 폰 안에서만 | 폰에 영어 목소리가 깔려 있으면 됨 | 됨 (폰 안 목소리) |
| 받아쓰기 | 폰 안에서만 | 안 될 가능성이 크다 (폰 안 받아쓰기는 데스크톱 크롬에 먼저 들어왔다. 폰에서는 확인 필요) | 안 됨 (폰 안에서만 하라고 시키는 길이 없다) |
| 받아쓰기 | 폰의 음성 인식 서비스 | 됨 (인터넷 필요, 소리가 구글로 간다) | 됨으로 안다 (받아쓰기를 켜 둔 폰. 홈 화면에 추가한 판에서는 안 될 수 있다) |
| 한국어로 옮기기 | 폰 안에서만 | 안 될 가능성이 크다 (폰 안 번역기는 데스크톱 크롬에 먼저 들어왔다) | 안 됨 |
| 한국어로 옮기기 | 폰의 음성 인식 서비스 | 번역 사이트 링크 | 번역 사이트 링크 |
| 녹음 | 둘 다 | 됨 | 됨 |
| 녹음과 받아쓰기를 같이 | 둘 다 | 폰마다 다르다 (마이크를 한쪽만 쓰게 하는 폰이 있다) | 같이 못 할 수 있다 |
| 손으로 적어 초안 만들기 | 둘 다 | 됨 | 됨 |

녹음과 받아쓰기가 부딪치면 앱이 "받아쓰기가 멈췄다, 녹음은 계속한다"고 알리고, "소리도 남기기"를 끄고 다시 하라고 안내한다.

## 폰 안 받아쓰기 모델

폰이 자체 받아쓰기를 못 할 때만 모델을 받을 수 있다. 확인 창에 크기와 와이파이 권장을 먼저 보이고, 확인을 눌러야 받기 시작한다. 실행기와 모델은 한 번 받으면 이 폰의 저장 공간에 남는다. 삭제 단추로 지울 수 있다.

| 부분 | 출처 · 판 | 라이선스 | 크기 |
|---|---|---|---:|
| 영어 받아쓰기 · Moonshine tiny | [ONNX 변환본](https://huggingface.co/onnx-community/moonshine-tiny-ONNX), 판 `a6da1241cd305dcd64eab1edbd615f2bb9aabb95`; 원본은 [Moonshine AI](https://github.com/moonshine-ai/moonshine) | MIT. [원본 라이선스](https://github.com/moonshine-ai/moonshine/blob/main/LICENSE)는 영어 tiny 모델을 MIT로 정한다 | 30.6 MiB |
| 실행기 · Transformers.js 4.3.2 | [npm](https://www.npmjs.com/package/@huggingface/transformers/v/4.3.2) | Apache-2.0 | 0.6 MiB |
| 실행기 · ONNX Runtime Web 1.31.0-dev.20260914-8d85527a0 | [npm](https://www.npmjs.com/package/onnxruntime-web/v/1.31.0-dev.20260914-8d85527a0) | MIT | 13.7 MiB |
| **합계** |  |  | **44.8 MiB (화면에는 약 45 MB)** |

폰에 남는 크기는 약 44.8 MiB(약 45 MB)다. 실제로 받을 때는 실행기 약 3.7 MB(gzip)와 모델 약 32.1 MB를 받아 총 약 36 MB가 왔다. 데스크톱 Chromium 157 헤드리스에서 받기 1.6 Mbps · 지연 150 ms로 흉내 내어 재니 받기와 모델 읽기까지 158초(2분 38초) 걸렸다. 모델을 받은 뒤 다시 열 때 읽기는 1.1초였다. 이 값은 실제 폰이나 실제 통신망의 기록이 아니다.

7.5초 영어 말을 이 모델로 받아 적는 데 0.50초 걸렸고, CPU를 네 배 늦춘 시험에서는 1.54초였다. 확인한 것은 데스크톱 Chromium 157 헤드리스뿐이다. 안드로이드 크롬 · 아이폰 사파리 · 파이어폭스는 확인하지 않았다. 받아쓰기 모델 파일 주소는 Hugging Face의 고정 판을 쓰며, 실행기 파일은 빌드 때 SHA-256과 크기를 확인한다.

실행기는 `onnxruntime-web` `1.31.0-dev.20260914-8d85527a0`으로 고정했다. 현재 npm의 안정판은 `1.31.1`(MIT)이고 CDN 파일도 있다. 안정판은 이 작업에서 package_check와 받아쓰기 회귀 시험을 하지 않아 바꾸지 않았다. 앞서 확인한 package_check의 빠진 것 0 · 주의 0은 현재 고정한 dev 판에 대한 결과다. 안정판으로 바꾸기 전에는 package_check와 같은 브라우저 시험을 다시 해야 한다.

이 모델은 **영어 받아쓰기만** 한다. package_check는 현재 실행기 두 패키지(Transformers.js 4.3.2 · ONNX Runtime Web 1.31.0-dev.20260914-8d85527a0)를 확인했고, 빠진 것 0 · 주의 0이었다. 이는 실행기 확인이며 번역 모델 확인은 아니다. 공식 en→ko ONNX 변환본은 찾지 못했다. 개인이 변환한 OPUS-MT 후보는 모델만 234 MB 이상이고, 각 변환본의 라이선스를 확인하지 못해 넣지 않았다. 원본 OPUS-MT의 CC-BY-4.0 표기만으로 변환본까지 허가됐다고 보지 않는다. 이미 폰 안에서 받을 수 있다고 확인된 브라우저 번역기만 쓰며, 준비되지 않았거나 크기를 알 수 없는 꾸러미는 자동으로 받지 않는다. 그래서 많은 폰에서 폰 안 영한 번역이 안 되며 R26은 아직 일부다. 폰 밖 길에서는 확인 뒤 번역 사이트 링크를 열 수 있다.

## 첫 화면 속도 시험

Playwright가 360 × 740 화면, CPU 4배 늦춤, 받기 1.6 Mbps · 보내기 750 kbps · 지연 150 ms로 다섯 번씩 쟀다. 처음 여는 화면은 FCP 중앙값 524 ms, 화면 완성 중앙값 893 ms(가장 늦을 때 1,097 ms)였다. 명함이 있는 첫 화면은 각각 532 ms · 813 ms(가장 늦을 때 838 ms)였고, 오프라인 두 번째 열기는 76 ms · 86 ms(가장 늦을 때 136 ms)였다. 모두 2초 안이다.

이 수치는 실제 폰이 아니라 Playwright 브라우저의 흉내이며, 압축하지 않은 임시 시험판에서 쟀다. 메모리 · 실제 회선 · 실제 폰에서 다시 확인해야 한다.

## 넣지 않은 것

- 들은 글을 줄이는 일은 폰 안에 요약기가 있을 때만 한다. 없으면 앞 세 줄을 "본 것"에 넣고 다듬으라고 적는다.
- 질문 묶음의 영어는 Orca가 쓴 초안이다. 어색한 말은 사람이 `data/phrases.json`에서 고친다.
